# Contract — gripper / end effector

The contract in force today, taken from `isaac_suction_bridge.py`, which states it
explicitly: *"Exposes the SAME ROS2 contract as the real fairino_gripper suction node,
so MoveIt / behavior trees / your code are IDENTICAL between Isaac and real hardware."*

## Interface

| | Name | Type |
|---|---|---|
| service | `/suction/on` | `std_srvs/Trigger` |
| service | `/suction/off` | `std_srvs/Trigger` |
| command | `/suction/cmd` | `std_msgs/String` — `"on"` / `"off"` |
| state | `/suction/joint_states` | `sensor_msgs/JointState` — joint `suctioncup_joint`, 0 open / 1 closed |

The state topic is merged into `/joint_states` by a joint-state merger, so the gripper
appears in the robot's state without the arm controller knowing about it.

A parallel or three-finger gripper exposes the same shape with a different profile: the
*names* are the contract, the *stroke and force* are the profile.

## Per backend

| | How the contract is met |
|---|---|
| `mock` | A no-op action server, currently **generated by TSA** into every bundle. It should become a stable node here — a fixed behaviour does not need generating. |
| `isaac` | `isaac_suction_bridge.py`, today in `<cell>_isaac/scripts/`. It answers the services and publishes a latched `std_msgs/Bool` on `/suction_cmd`; an OmniGraph Script Node inside the USD reads that and drives the `SurfaceGripper`. |
| `real` | `fairino_gripper`, which issues `SetDO` on the Fairino controller. |

## Migration pending

Both `mock` and `isaac` adapters belong in this package. They are not moved yet because
doing so changes `deployment.bridges` in the generated bundle, which forces a
regeneration and a fresh end-to-end Isaac test. Tracked in the decision log.
