# TrainIt hardware layer

The **contracts** every hardware role exposes to ROS, the **profiles** that describe a
specific piece of hardware in those terms, and the **adapters** that realise a contract
on a given backend.

```
contracts/   what a role must expose        robot · gripper · camera
profiles/    what THIS hardware is          fairino_fr3wml · softgripper_suction · realsense_d455
adapters     one contract, one backend      mock_camera · mock_eef_adapter · isaac_eef_adapter
```

## Why it exists

The pattern was already in the code, spread across three different homes: a vendor
package, the cell's `_isaac` package, and a file **regenerated into every bundle**. Two
projects had grown the same scatter independently. This package gives it one place and
writes the contract down instead of leaving it in docstrings.

The rule it enforces: **application code names the contract, never the backend.** A
behaviour tree commands an end effector by its logical id (`CloseGripper eef="main"`); whether
the command reaches Isaac, a vendor controller or a mock is a launch argument.

## Use it

```python
from trainit_hardware_layer import profiles

cam = profiles.load('camera', 'realsense_d455')
profiles.backend(cam, 'isaac')          # what implements the contract in this mode
profiles.available('camera')            # what this layer knows about
```

```bash
ros2 run trainit_hardware_layer mock_camera            # the camera contract, no simulator
ros2 run trainit_hardware_layer mock_camera --ros-args -p plane_distance_m:=1.5
```

## The end-effector adapters (ADR-0022, 0.2.0)

The canonical end-effector contract ([`contracts/gripper.md`](contracts/gripper.md)) is served by
two adapter rows. Each process serves ONE device, in the robot's namespace, and reads the SAME
`eef.<id>.*` parameter block TMR reads (TSA generates both from one project):

| Row | Executable | Serves | State |
|---|---|---|---|
| `trainit_mock` | `mock_eef_adapter` | every actuator on its standard interface: SetBool `eef/<id>/actuators/<a>/set_engaged`, and GripperCommand / FollowJointTrajectory at their declared actions, emulating a GripperActionController and a joint_trajectory_controller | `eef/<id>/state`, with a scripted sensor per site; failures injected by parameters only |
| `trainit_isaac_surface_gripper` | `isaac_eef_adapter` | one binary suction vacuum, onto an Isaac SurfaceGripper through two std_msgs topics (`stage_cmd_topic` required; `stage_status_topic` optional) | `eef/<id>/state`; the grasp only from the stage's own status (SIM_GROUND_TRUTH), else UNAVAILABLE |

```bash
# eef_main.yaml: /**: {ros__parameters: {device_id: main, eef: {main: {...}}}} -- the device's
# block as TSA generates it; a launch file passes the same keys as a nested parameter dict.
ros2 run trainit_hardware_layer mock_eef_adapter --ros-args -r __ns:=/r1 --params-file eef_main.yaml
ros2 topic echo /r1/eef/main/state
ros2 service call /r1/eef/main/actuators/vacuum/set_engaged std_srvs/srv/SetBool "{data: true}"
```

Both refuse a malformed contract or a bad parameter at start-up with exit code 2, naming the key
(as TMR's runner does). The parameters are documented in the module docstrings
(`trainit_hardware_layer/eef/adapter_node.py`, `mock_eef_adapter.py`, `isaac_eef_adapter.py`).
Compatibility endpoints (the policy card's Trigger pair, the description's pseudo-joint echo, a
GripperCommand suction handle) are off unless a parameter enables them.

The pure parts are importable without a ROS graph: `trainit_hardware_layer.eef.contract` (the
block's parser, behaviourally identical to the vNext M2.6 reference normaliser) and
`trainit_hardware_layer.eef.core` (the state model). Tests: `colcon test` (pytest + rclpy on the
private ROS domain 86, behind a graph guard).

## Status

| Role | mock | isaac | real |
|---|---|---|---|
| robot | external | external | external |
| **gripper**, canonical (ADR-0022) | **here** (`mock_eef_adapter`) | **here** (`isaac_eef_adapter`) + the stage-side script | `ros2_control` via the vendor bring-up, or none |
| gripper, legacy | generated by TSA | the cell's `isaac_suction_bridge.py` | vendor package |
| **camera** | **here** | Isaac Camera Helper — no node needed | Jetson container |

Vendor adapters stay in their own repositories: they are the vendor's, not TrainIt's.
This layer *declares* them in a profile.
